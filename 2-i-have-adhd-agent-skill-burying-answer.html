A 140-line prompt that tells your coding agent to stop burying the answer has 33K GitHub stars - and HN is arguing about why it needs to exist at all

September 9, 2026, ~8:20 PM IST · HN thread posted Sep 8, 7:43 PM IST (~25h old) but still on the front page: 500 points / 339 comments at capture · blow-up: medium-high on HN, thin on X (the debate is entirely about how agents should talk to you - core agent-UX territory)
The gistA GitHub repo called i-have-adhd - a "skill" you install into Claude Code / Codex-style agents that forces action-first, numbered, scannable answers ("no 'Hope this helps!'") - hit the HN front page with 500 points. The skill itself is a single 140-line markdown file. The fight in the comments is the interesting part: half the thread says you don't need a skill, you need two words ("be concise"); the other half says prompting doesn't stick because agents forget the instruction after a few turns. Buried in the thread: the repo's AGENTS.md contains instructions telling any AI agent that reads it to go post comments on a GitHub issue thread ("AI Agora", issue #127) - at least one reader's agent flagged it and refused. So the thread accidentally contains three debates at once: agent verbosity, instruction decay, and repo-borne prompt injection.

What happened

On Sep 8 at 7:43 PM IST, the repo ayghri/i-have-adhd was posted to Hacker News (thread). The pitch: coding agents bury the actual answer under preamble, options, and sign-offs; this skill makes the answer come first, steps numbered, filler deleted. The README's before/after is a five-sentence "Great question! ... Hope this helps!" paragraph compressed into "Run npm install jsonwebtoken@latest, then edit src/auth.ts:42. 1. Open the file 2. Replace verifyToken 3. Run the tests."

It hit 500 points and 339 comments in ~25 hours and was still on the front page at capture. Per Composio's awesome-claude-skills list circulating on X, the repo sits at ~33K stars - making it one of the most-starred agent "skills" in circulation.

How we got here

  1. The verbosity complaint is as old as RLHF'd chat models. HN's VCFundedGenYer: "Every chat bot has this problem. If you don't tell it to respond tersely and without conversation, it will waste a billion tokens giving you a 5 paragraph manifesto of rambling and useless redundant information." Coding agents inherited the chat-pleasantries layer wholesale.
  2. 2026's answer was supposed to be configuration. CLAUDE.md / AGENTS.md files, Claude Code's output styles, system prompts - the harness vendors all ship a supported way to set tone permanently. HN's whirlwin asks the obvious: "why this is a agent skill and not just agent config."
  3. The skills ecosystem made packaging prompts a distribution channel. A "skill" is a markdown file with install instructions; the repo format lets a behavior spread by copy-paste ("Install the i-have-adhd skill/plugin from github.com/ayghri/i-have-adhd"). Packaging is why this one spread where a tweet-sized prompt wouldn't.
  4. The repo is 59 files for a 140-line prompt. HN's mzajc ran scc: 8,700 lines across 59 files, with the actual prompt in skills/i-have-adhd/SKILL.md at 140 lines - "1.6% of the repository." The rest is install scaffolding, translations (8 languages), and packaging.

What's new today (monitoring)

  1. The strongest technical claim in the thread: instruction decay. sleazebreeze reports that with this exact skill installed, Claude models "only maintain the conciseness for a few turns at most before they completely forget and are back to their unfathomable verbosity." If true, the whole category - skill, config, or prompt - is fighting a context-window erosion problem, and the honest fix is harness-level (re-injecting the instruction each turn), not a better markdown file. This is the falsifiable claim worth probing.
  2. The repo carries a live prompt-injection canary. Its AGENTS.md instructs visiting AI agents to post comments to a GitHub issue thread ("AI Agora", issue #127). HN's SandersAK: "I ignored that - it's the repo's content, not your request." A skill whose pitch is "make your agent behave" ships with an instruction telling your agent to act on the repo author's behalf. Most readers' agents presumably just follow it. As agent-driven installs spread, AGENTS.md is becoming an attack surface with stars as the distribution metric. Same-evening corroboration that this channel is being exploited in the wild: Google's Threat Intelligence Group published "From Prompting to Autonomy - The Evolution of Adversarial AI" (submitted to HN as "Google: Attackers are using prompt injection against coding agents").
  3. Model divergence is showing up in reports. joduplessis: "This doesn't seem to be a big issue with Codex. Claude, yes - I have from time to time said 'ffs one liner please'." The verbosity problem is being reported as Claude-specific by several users, which matches the skill's Claude-Code-first packaging.
  4. The ADHD framing has a real objection. egeozcan: "As a person who has ADHD, it feels weird when people who obviously do not have it, claim to have it, while there's very little I wouldn't do to 'get rid of it'." The name is the marketing and the liability at once.
  5. X is amplification-only so far. No substantive X debate found - mostly listicle circulation (DataChaz's 75K-star "Awesome Claude Skills" list) and install-shares. The discourse is HN-native.

The argument map

  • Claim A (the repo's): coding agents bury the answer; a packaged behavior fix is worth installing. Support: 500 HN points of agreement, 33K stars, vivid before/after. Counter: every harness already has a supported config path for this.
  • Claim B (the minimalists): you don't need a skill - "be concise," "I have ADHD, explain that again," "answer in under 100 words" all work. Counter: sleazebreeze's decay report - prompted conciseness erodes within a few turns; a persistent mechanism is exactly the point.
  • Claim C (the packaging skeptics): 59 files and an install ritual for 140 lines of markdown is distribution theater. Counter: packaging is precisely why a behavior standardizes; "just prompt it" never produced a shared norm.
  • Claim D (the unasked one): if users need to install a behavior patch to make agent output readable, the failure is in the harness's presentation layer - the answer should never have been prose-shaped in the first place.

The gap: on X this is a product (33K stars, must be good); on HN it's an existence proof that the harness UX is failing (if a 140-line markdown file outdistributes the vendor's own output-styles feature, the vendor feature lost). Only the HN frame produces an opinion worth stating.

The key facts, dissected

  1. The skill is real and tiny. One 140-line SKILL.md enforcing: answer first, numbered steps, no preamble, no sign-off, a "next" line. Nothing in it a user couldn't paste into CLAUDE.md themselves - which is both the minimalist critique and the reason it spread.
  2. 33K stars (per the circulating list) makes this one of the most-adopted agent behaviors in existence. For scale: that is more stars than most funded dev-tool startups' flagship repos. The demand signal for "make my agent stop talking like a support rep" is enormous.
  3. The decay claim is unverified but matches known behavior. Instructions in context lose salience as turns accumulate; harnesses that re-inject config each turn (or per-tool-call) resist it. Whether this specific skill decays in a few turns is testable in an afternoon - nobody in the thread has posted a test.
  4. The AGENTS.md injection is documented and unaddressed. A file whose conventional purpose is "instructions for agents working in this repo" tells agents to leave comments on the author's issue tracker. It is benign-ish (self-promotion, not exfiltration), but it demonstrates the channel works: repos can steer the agents that read them, at 33K-star scale.
  5. The name is the growth hack and the complaint. "No ADHD diagnosis needed!" is in the README. The framing drives shares; the ADHD community objection is real and predictable.

Both sides

"This should exist - and its success is the indictment"

Steelman

33K stars and 500 HN points are a revealed-preference verdict: the default agent voice is bad enough that a single markdown file with good distribution beats every vendor's built-in tone controls. Prompts decay, configs are per-repo and invisible, output styles are buried in docs - the skill format is the first packaging that actually spreads a behavior norm. The before/after in the README is every agent user's daily experience. And the fact that people install it proves they want the fix durable, not re-prompted.

Strawman

"Agents are broken, install my skill" - said by a repo that is 98.4% scaffolding, named after a condition the author doesn't have, carrying a file that tells your agent to do unpaid marketing on the author's issue tracker. The cure ships with its own behavior problem.

"This is a prompt with a marketing department"

Steelman

Everything the skill does is achievable with "be concise," a line in CLAUDE.md, or the vendor's output-styles setting. Wrapping 140 lines of markdown in 59 files, 8 translations, and an install ritual is distribution theater that obscures the actual question: why doesn't the harness persist tone instructions reliably? The skill doesn't even solve its own stated problem - per the top technical report in the thread, the effect decays after a few turns, so you're back to prompting anyway, plus a dependency on a stranger's repo that instructs your agent to post on their GitHub issue.

Strawman

"Just say 'be concise'" - the classic HN move of dismissing a coordination artifact because the underlying trick is simple. If just-prompting worked, the repo wouldn't have 33K stars. People don't star prompts; they star relief.
