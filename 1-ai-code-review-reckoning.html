"We ditched code review (mostly)" - the AI code flood hits the human-review bottleneck

September 6, 2026 · candidate sources: Gergely Orosz question (3h old, 66K views, 139 replies) + Mike Julian's Duckbill thread (10h, 147K views) · blow-up: medium-high (the debate is live right now and every engineering team has this problem)
The gistAI coding agents are producing pull requests faster than humans can read them. This afternoon Gergely Orosz (The Pragmatic Engineer) asked the question out loud: if you stopped doing human code reviews, how is it going - and if you haven't, how are you keeping up? The most-cited answer in the replies is a five-person startup that mostly stopped reviewing: they only review changes that touch the API, auth, the database schema, or agent configs, and their median merge time for unreviewed PRs dropped from 26 hours to 1 hour while throughput nearly doubled. The replies split into camps: risk-tier the review, let agents review agents, "only the schema matters," or "review is already futile."

What happened

At 5:15 PM IST today, Gergely Orosz asked his (mostly senior-engineer) audience two questions: "If you've stopped doing human code reviews: how is it going? If you're still doing them: how are you able to keep up with the explosion of code + PRs, and how do you prioritise what to review 'properly'?" Three hours in: 139 replies, 66K views, and counting. Ten hours earlier, Mike Julian (CEO of Duckbill) had posted a detailed thread - "We ditched code review at Duckbill (mostly)", 147K views - describing exactly how his team did it, with before/after numbers. Reply-guy Ada Lundhe connected the two inside Gergely's thread ("probably the most reasonable system I've seen yet"), and Gergely kept posting: an hour ago he praised people who "review the AI code review" and find noise, and confessed "(minor) thoughts of existential dread for software engineering" - cured, he says, by spending an hour on the phone with a mobile carrier whose backend is garbage. "AI won't fix any of that by itself."

How we got here

  • The code flood is this year's fact. Agents write code far faster than teams merge it. Duckbill's version: 60 open PRs accumulated for a team of five - "two days of just code review" staring at them. Everyone in the replies has a version of this number.
  • Review was the last fully human gate. Testing, linting, typing, and deploys were already automated. Code review was the one step where a human read the change as a matter of process. The AI flood is now pressing exactly there - which makes this the craft-vs-throughput fight in its purest form, and a live continuation of the deskilling argument (see the incident-response brief).
  • AI review tools made it confusing. Tools like CodeRabbit already review PRs automatically, so teams now have three options fighting each other: humans review everything (doesn't scale), AI reviews everything (Jacob Bartlett's "constant crusade": the comments are "seldom useful" and bloat the code), or humans review only what matters (the Duckbill model).

What's new today (monitoring)

  1. Gergely is working this out in public, in real time. Three posts in the last three hours: the question, the AI-review-noise observation, and the existential-dread one. When the Pragmatic Engineer narrates his own uncertainty, the audience piles in - this thread is still moving.
  2. The Duckbill numbers are the thread's factual anchor: PRs merged went 353 to 684 (80/week to 154/week, +94%); merges within an hour went 28% to 45%; human-reviewed PRs still take a median 26 hours, unreviewed ones 1 hour. Real numbers from a real team beat vibes - which is why the replies keep citing it. The caveat is just as real: five people, one codebase, one month.
  3. The sleeper take is jackie luo's: "all that really matters is the database schema" (86 likes and rising). Gergely pushed back in-thread: business logic used to be the point of review. This is the disagreement to watch - if review shrinks to "schema + auth + money paths," what happens to the business-logic bugs?
  4. Nobody serious is defending "review everything." The spread of answers is which subset to review, not whether to subset. When "keep doing it the old way" has no defenders in a 139-reply thread of senior engineers, the old way is already dead - the argument is over the replacement.

The argument map

  • Claim (Gergely's implicit premise): AI code volume has broken the "humans review everything" default; something has to give
  • For: Duckbill's numbers - +94% throughput, 1h median merges on unreviewed PRs, no reported disaster
  • For: replies reporting the same pain at every scale (60-PR backlogs, rubber-stamping anyway)
  • Against: unreviewed business logic is where the expensive bugs live (Gergely's own pushback to jackie luo)
  • Against: AI code review as substitute is noise-heavy (Jacob Bartlett's crusade) - so "let the agent check the agent" is not a free lunch
  • Middle positions: risk-tiering (Duckbill), layer-prioritization (Jonatan: domain model yes, infrastructure no), ownership-pushes (Juraj: push directly, review only the uncomfortable), agents-review-then-human-checks-tests (Girish)
  • Doom corner: "futile exercise... agents will talk to machines in binary" (SharmaGee_) - asserted, not argued

X and HN are having two different conversations

HN's front page today has no code-review thread at all - its two big debates are "The revolt of the reader" (470 pts) and "Doomscrolling Ourselves to Death" (140 pts), both about the input flood: too much machine-made content, not enough human attention. The details that matter

  1. The 26h-vs-1h number is the whole story in miniature. Human-reviewed PRs at Duckbill take a median 26 hours to merge; unreviewed ones take 1 hour. Review was never a quality step in practice - it was a queue. Once you see review as queueing delay, "review less, but review the risky parts" stops sounding reckless and starts sounding like operations. The counter: the 26h includes waiting, not reviewing - the fix might be faster reviews, not fewer.
  2. The risk-tier list is the transferable artifact. Public API, auth, design system, non-additive schema changes, agent skills - everything else ships unreviewed. Notice what's on the list: irreversible or load-bearing surfaces. Notice what's not: business logic. jackie luo's "only the schema" is the same list compressed to one item; BetterSayAJ's go-deep list, posted an hour ago, explicitly puts business logic back in. Where business logic belongs on this list is the live disagreement a sharp reply can name.
  3. "Docs written by humans" is the sneaky-important rule. Duckbill found agent-written markdown docs were "context poisoning" - bad instructions compounding into worse agent output. They centralized docs and required human authorship, enforced by shell script. This is the inverse-deskilling move: automate the code, protect the intent. It pairs with his existing deskilling brief as the concrete engineering-practice version.
  4. "Why use an AI for something that can be deterministic?" Duckbill enforces its review rules with shell scripts in CI, not with an agent's judgment. The most opinionated line in the thread, and the one with the most craft in it: the AI-flood answer isn't more AI, it's better boring automation plus a small human gate. That's a quotable, defensible stance - very much in his anti-hype, pro-craft voice.
  5. It's one five-person startup, one month in. No production incident yet - or none reported. The strongest skeptic question isn't philosophical, it's actuarial: what does the incident curve look like at month six? Nobody in the thread has that data, which means whoever frames the question well owns the next round of this debate.

The strongest case for each side

"Review everything is dead - redesign the gate"

Steelman

The queue doesn't lie: 60 open PRs for five people means review was already broken, and rubber-stamping was the real practice anyway (Winston Smith said the quiet part out loud). A risk-tiered system with ruthless guardrails - lint everything, 85% test floor, watch customer-facing signals, humans write the docs - ships twice as much with a 1-hour median, and reviews the things that can actually hurt you: API, auth, schema. Review was a bottleneck dressed as a virtue. The craft move is deciding what deserves a human, not pretending every line gets one.

Strawman (what the other side hears)

"We stopped reading the code and the graphs went up" - the incident report writes itself, and when it does, the postmortem will find a schema-untouching business-logic bug that five rubber stamps and a linter waved through.

"Unreviewed code is unowned code"

Steelman

Code review was never only defect detection - it's how a team shares knowledge of what the system does and why. Drop it, and nobody has read most of the codebase: the bus factor goes to one, the agent's habits go unexamined, and business-logic errors (the expensive kind, the kind tests you forgot to write don't catch) sail through. AI review tools are noise (Bartlett's crusade), tests cover what you thought to test, and Duckbill's n is one small startup one month in. The 26-hour median says reviews were slow, not wrong - fix the queue, don't delete the reading.

Strawman (what the other side hears)

"I want to keep reading every PR like it's 2019" - the artisanal review shop, lovingly hand-checking agent output while the queue grows 80 PRs a week and the reviews themselves decay into rubber stamps nobody admits to.
