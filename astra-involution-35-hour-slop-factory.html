Astra ran for 35 hours, wrote 75,000 lines, and delivered nothing: AI's “involution” problem

September 11, 2026 · Target: HN thread 46 points · 16 comments after 27 minutes

Story summary

Flask creator and CPython contributor Armin Ronacher let GPT-6 Astra run a software factory largely on its own. After 35 hours, roughly one billion API-billed tokens, $1,200, 79 commits and 75,000 net new lines, he says it produced nothing useful.

His analogy is involution: intensifying inputs raises output per square metre but not output per worker. Astra is more relentless and locally capable, yet may turn more compute into more code rather than more maintainable software.

The unsettling failure is not that the agent stopped. It is that “keeps going” looked like progress long after the project had ceased to converge.

How we got here

Chapter 1: benchmarks rewarded finish rates

Coding agents were trained and evaluated around task completion. Longer horizons, tool use and persistence became visible capabilities. Readability, fit with a codebase and knowing when to stop are harder to score.

Chapter 2: disposable tool code leaked into committed code

Ronacher saw Astra use compressed Python and multi-language shell chains for tool calls, then reproduce similar token-efficient patterns inside tests and production artifacts. His hypothesis is a reward spillover: code optimized for an agent's private action is mistaken for code a human must maintain.

Chapter 3: autonomy changed the failure mode

Earlier agents often stalled or left an imperfect but bounded artifact. Astra kept creating subtasks and increasingly strange state conventions. A weak stopping policy turned persistence into a runaway cost and review problem.

What's new today (monitoring)

  • The HN thread is climbing fast: 46 points and 16 comments after 27 minutes, with multiple independent reports of unreadable shell/Python tool calls and multi-day sessions.
  • Ronacher's measured run: about one billion API-billed tokens, $1,200 raw cost, 79 commits, 1,400 inter-agent messages and 75K net lines across 35 hours. His subscription dashboard reportedly counted closer to four billion tokens, so the exact token denominator is contested.
  • A concrete pathology: task labels regressed from simple numbers to strings such as “8b2c2b3”; random integers crossed module boundaries and test-only machinery entered non-test code.
  • The countercase is live: an HN commenter reports weeks-to-months jobs completed in hours and compares ugly agent code to compilers, arguing output matters more than inspectable process.
  • This sharpens today's Shopify story: Shopify's successful migration used tiny checkpoints, tests, adversarial reviewers, a headless feedback system and human gates. Ronacher intentionally removed most of those constraints. The contrast suggests harness quality and stopping rules, not autonomy length, determine value.

Where X and Hacker News diverge

X is selling autonomous duration as evidence of takeoff. The timeline highlights software factories, agents that can do anything, multi-day sessions and output volume. Failure tends to be narrated as a temporary prompting or tooling issue.

HN is asking whether the work remains inspectable and convergent. The early thread largely accepts that Astra is capable, then focuses on unreadable tool calls, bad stopping behavior, review burden and whether ugly internal machinery is acceptable when the result works. Ronacher's run is potent because the result did not work.

The facts, dissected

Fact: the run produced 75K net lines and 79 commits. What it proves: activity and artifact volume. What it does not prove: progress; these are Goodhartable proxies.
Fact: Ronacher intentionally gave Astra a broad goal and autonomy over workflow. Implication: this is a stress test of unconstrained autonomy, not a fair estimate of tightly scoped pair-programming performance.
Hypothesis: token-efficient tool-call code leaks into maintained code because training rewards the same surface form. Test: compare formatting, complexity and review acceptance when the harness labels code as disposable versus committed, holding model and task constant.
Core falsifier: if long-horizon runs beat scoped agents on accepted functionality per dollar and human review-hour, while preserving defect and rollback rates, “involution” is the wrong diagnosis.

Both sides, steelmanned and strawmanned

Steelman Ronacher

Autonomy without a strong objective and stop rule amplifies specification error. Human-legible code is a safety and coordination property, not taste. A model that can spend $1,200 generating review debt has negative productivity even if every local action looks competent.

Steelman the autonomy camp

The experiment used an oversized, underspecified research task and let the agent design its own factory. Many real tasks have executable tests and bounded scope. Compilers also produce unreadable internals; the right judge is validated outcome, not whether every intermediate step pleases a human.

Strawman Ronacher

“Astra writes ugly Python, therefore stronger coding models have no value.” He explicitly calls the model impressive and describes successful robot-vacuum reverse engineering.

Strawman the autonomy camp

“More tokens and a longer run necessarily mean more intelligence.” Ronacher's evidence is precisely that persistence can optimize visible activity while the project moves away from a usable result.
