What happened

At 4:55 AM IST, Theo posted: "I'm increasingly confused why people think 'agent memory for enterprise/teams' is a real product category that makes any sense at all." Then he defended it in the replies. His actual position, pieced together from his follow-ups: memory for agents is real, but it should be "adjustments to the system prompt, or, at the absolute worst case, a manually curated set of skills and 'knowledge'" - and "I just cannot fathom how a product automating this would be any good and not cause more problems than it hypothetically solves." Asked what purpose such products serve, his answer: nothing that "isn't served better with really basic updates to the Markdown files, giving context to agents."

For context if you're new to this: "agent memory" means the notes an AI assistant keeps between sessions - what it learned about your codebase, your team, your preferences. Startups like Mem0, Letta, and Zep sell this as a service. The free alternative is a text file in your repo (CLAUDE.md, AGENTS.md) that the agent reads every time. Theo is saying the text file wins.

How we got here

  • Agents got long-running, and memory became the bottleneck. Once coding agents started working for hours instead of minutes, "what does it remember tomorrow" went from a research question to a product question. Every long session re-teaches the agent the same things - that's the pain the category sells against.
  • A startup wave formed around it. Mem0, Letta (the MemGPT team), Zep, and a dozen smaller tools all sell hosted memory for agents. The enterprise pitch: your whole team's agents share one memory, so knowledge doesn't die inside individual chat sessions.
  • The counter-tradition is the humble text file. Claude Code's CLAUDE.md and the AGENTS.md convention made "memory = a markdown file you curate" the default for individual developers. Theo's whole workflow is public and file-based, so this post is him defending his own stack.
  • The category had a launch week right before the attack. In the four days before Theo's post, Hacker News saw at least five memory launches (details below). Theo isn't attacking a hypothetical - he's attacking a category that was visibly forming this week.

The strongest case for each side

"Memory is a config problem, not a product"

Steelman

Every memory layer that's been bolted onto an agent has shipped the same failure modes: stale facts retrieved with full confidence, wrong "memories" written automatically and never audited, and retrieval noise that makes the agent dumber, not smarter. The wins people attribute to memory products come from the 20% that was always just a curated document. A markdown file in the repo is versioned, reviewable, diffable, and owned - a hosted memory service is none of those. Auto-written shared memory at company scale isn't a brain, it's a rumor mill with an API. The category exists because "memory" sounds like a moat, not because the product shape works.

Strawman (what the other side hears)

"This is the next system of record"

Steelman

Right now every employee's agent learns the company from scratch and the knowledge evaporates when the session ends. Multiply that by a thousand employees and you get a thousand divergent private versions of how the company works. Shared agent memory is how the organization compounds what it learns instead of re-learning it daily. And the real buyer need isn't fuzzy recall - it's governance: who taught the agent what, what's the audit trail when it's wrong, what gets forgotten when someone leaves. Nobody sells that as markdown files. Salesforce for the agent era is a category; the only question is who builds it.
